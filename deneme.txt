3.  Aldığın cevaplara göre proje için en uygun:
    -   Klasör yapısını (Directory Structure)

    -   Ve "AI Kuralları"nı belirle.

  Adım 1: Proje Vizyonu ve Kapsamı

  Öncelikle ne inşa edeceğimizi tam olarak anlamam gerekiyor. Lütfen aşağıdaki soruları cevaplayarak bana projeni anlat:

  1. Projenin Ana Fikri: Bu proje nedir? (Örn: Bir e-ticaret sitesi, bir SaaS yönetim paneli, bir mobil oyun arka ucu, bir blog platformu vb.)
  2. Temel Amaç: Hangi problemi çözüyor veya kullanıcıya sunduğu temel değer nedir?
  3. Ana Özellikler (MVP): İlk etapta olmazsa olmaz dediğin 3-5 özellik nedir?
  4. Proje İsmi: Eğer henüz yoksa geçici bir isim de verebilirsin.

  Cevaplarını bekliyorum, ardından teknik detaylara (Adım 2) geçeceğiz.

● Harika, proje vizyonu oldukça net ve pazar değeri yüksek bir alan. "Zaman tasarrufu" ve "karmaşık veriden anlamlı rapor çıkarma" vaadi, özellikle kurumsal dünyada çok kıymetli.

  Şimdi bu vizyonu teknik bir iskelete oturtmak için Adım 2: Teknoloji ve Altyapı Kararları aşamasına geçelim.

  Aşağıdaki konularda tercihlerini öğrenmem gerekiyor. Eğer emin değilsen, parantez içinde (Önerim: ...) şeklinde belirttiklerimi onaylayabilirsin.

  1. Platform ve Dil

  Bu uygulamayı nasıl sunacağız?
  - Platform: Web uygulaması (Tarayıcıda çalışan SaaS) mı, yoksa Mobil uygulama (iOS/Android) mı?
    - (Önerim: Dashboard ve detaylı raporlama dediğin için Web Uygulaması (Responsive) olarak başlamak en mantıklısı.)
  - Programlama Dili & Framework:
    - Frontend (Önyüz): React, Vue, Angular? *(Önerim: Next.js (React). Hem hızlı, hem SEO dostu, hem de güncel standart.)*
    - Backend (Arka Yüz): Python (Django/FastAPI) mı, Node.js mi? (Önerim: Eğer Next.js kullanırsak, backend'i de Next.js API Routes (Node.js/TypeScript) ile içinde halledebiliriz. Bu geliştirme hızını artırır.)

  2. Yapay Zeka ve Veri İşleme

  Uygulamanın kalbi burası.
  - LLM (Dil Modeli) Sağlayıcısı: Raporları yazmak için hangi zekayı kullanacağız?
    - (Önerim: OpenAI (GPT-4o) veya Anthropic (Claude 3.5 Sonnet) API'ları. Hem metin hem de görsel (OCR) analizi için şu an en iyileri bunlar.)
  - Görsel İşleme (OCR): Fotoğraflardan veri çekmek için.
    - (Önerim: GPT-4o veya Claude 3.5 Vision özellikleri zaten bunu yapıyor, ekstra bir OCR kütüphanesine (Tesseract vb.) gerek kalmayabilir, API üzerinden halledebiliriz.)

  3. Veritabanı ve Dosya Saklama

  - Veritabanı: Kullanıcıları, rapor taslaklarını ve istatistikleri nerede tutacağız?
    - *(Önerim: Supabase (PostgreSQL). Hem veritabanı, hem kimlik doğrulama (Auth), hem de dosya depolama sunuyor. Kurulumu çok hızlı.)*
  - Dosya Depolama: Yüklenen fotoğraflar ve PDF'ler nerede duracak?
    - (Önerim: AWS S3 veya Supabase Storage.)

  4. Tasarım ve UI

  - Arayüz Kütüphanesi: Hızlı ve şık bir dashboard için ne kullanalım?
    - (Önerim: Tailwind CSS ve shadcn/ui. Şu an sektör standardı, çok temiz ve profesyonel duruyor.)

  Özetle bana şu şekilde dönebilirsin:

  "Önerilerini kabul ediyorum" diyebilirsin veya değiştirmek istediğin yerleri belirtebilirsin. Özellikle Python kullanmak isteyip istemediğin önemli bir detay (AI kütüphaneleri genelde Python odaklıdır ama API kullanacaksak TypeScript/Node.js daha pratik olabilir).

  İsteğine göre, "$0 Başlangıç Maliyeti" mimarisini kurguladım. İşte cebinden para çıkmadan bu projeyi ayağa kaldırmanı sağlayacak "Bootstrap Stack" önerim:

  1. Platform & Barındırma (Hosting)

  - Seçim: Next.js (App Router) + Vercel
  - Neden: Vercel'in "Hobby" paketi kişisel projeler ve ticari olmayan ilk denemeler için tamamen ücretsizdir. Next.js ile yazdığımız uygulamayı tek tıkla yayınlarız. SSL sertifikası, alan adı (vercel.app uzantılı) her şey ücretsiz gelir.

  2. Veritabanı & Backend Servisleri

  - Seçim: Supabase
  - Neden: Firebase'e göre daha yapısal (SQL) olduğu için raporlama verilerine daha uygun. Ücretsiz planı (Free Tier) sana şunları verir:
    - 500 MB Veritabanı (Başlangıç için devasa bir alan).
    - Ayda 50.000 aktif kullanıcı (MVP için fazlasıyla yeterli).
    - Auth (Google ile giriş, E-posta ile giriş) ücretsiz.
    - Dosya Depolama (1 GB) ücretsiz.

  3. Yapay Zeka (LLM) & Raporlama

  - Seçim: Google Gemini API (Gemini 1.5 Flash veya Pro)
  - Neden: OpenAI paralıdır. Ancak Google, geliştiriciler için Gemini API'da cömert bir ücretsiz kota sunar (dakikada belirli bir istek sayısına kadar ücretsiz).
    - Raporları yazmak için Gemini'yi kullanırız.
    - Hız ve maliyet dengesi için harika bir seçenek.

  4. OCR & Görüntü İşleme

  Burada hibrit bir yapı kuralım:
  - Seçenek A (Basit Metinler): Tesseract.js. Bu bir kütüphanedir, sunucu veya API gerektirmez, doğrudan kullanıcının tarayıcısında veya bizim sunucumuzda çalışır. Maliyeti 0 TL.
  - Seçenek B (Karmaşık Tablolar/El Yazıları): Gemini Vision. Yukarıda bahsettiğim ücretsiz Gemini kotası, sadece metin değil resim de okuyabilir. Fotoğrafı Gemini'ye atıp "Bunu analiz et ve JSON verisine çevir" diyebiliriz. Bu da ücretsiz kotaya dahildir.

  5. Arayüz (UI)

  - Seçim: shadcn/ui + Tailwind CSS
  - Neden: Tamamen ücretsiz, açık kaynak ve kopyala-yapıştır mantığıyla çalışır. Lisans ücreti yok.

  import { NextRequest, NextResponse } from 'next/server'
  import { geminiVisionModel } from '@/lib/gemini'

  export async function POST(req: NextRequest) {
    try {
      const formData = await req.formData()
      const file = formData.get('file') as File

      if (!file) {
        return NextResponse.json({ error: 'Dosya yüklenmedi.' }, { status: 400 })
      }

      // Dosyayı ArrayBuffer'a çevir
      const arrayBuffer = await file.arrayBuffer()
      const buffer = Buffer.from(arrayBuffer)
      const base64Data = buffer.toString('base64')

      // Gemini'ye gönderilecek format
      const imageData = {
        inlineData: {
          data: base64Data,
          mimeType: file.type,
        },
      }

      // Vision Prompt
      const prompt = "Bu resimdeki tüm yazıları, notları ve tabloları detaylıca oku ve metin olarak dışarı aktar. Sadece içeriği ver, yorum yapma."

      const result = await geminiVisionModel.generateContent([prompt, imageData])
      const response = await result.response
      const text = response.text()

      return NextResponse.json({ text })
    } catch (error) {
      console.error('OCR Error:', error)
      return NextResponse.json(
        { error: 'Resim okunurken hata oluştu.' },
        { status: 500 }
      )
    }
  }

  Adım 1: Veritabanı Tablolarının Kurulumu 🗄️

  Önce verileri saklayacağımız tabloları Supabase üzerinde oluşturmalıyız.

  Bu SQL kodu şunları yapacak:
  1. profiles: Kullanıcı bilgilerini tutacak tablo.
  2. reports: Oluşturulan raporları tutacak tablo.
  3. Güvenlik (RLS): Herkesin sadece kendi raporunu görmesini sağlayacak kurallar.

  İşte SQL kodu:

  -- 1. Kullanıcı Profilleri Tablosu
  create table public.profiles (
    id uuid not null references auth.users on delete cascade,
    email text,
    full_name text,
    avatar_url text,
    created_at timestamp with time zone default timezone('utc'::text, now()) not null,
    primary key (id)
  );

  -- RLS (Güvenlik) Aç
  alter table public.profiles enable row level security;

  -- Herkes kendi profilini görebilir ve düzenleyebilir
  create policy "Public profiles are viewable by everyone." on public.profiles for select using ( true );
  create policy "Users can insert their own profile." on public.profiles for insert with check ( auth.uid() = id );
  create policy "Users can update own profile." on public.profiles for update using ( auth.uid() = id );

  -- 2. Raporlar Tablosu
  create table public.reports (
    id uuid default gen_random_uuid() primary key,
    user_id uuid references public.profiles(id) on delete cascade not null,
    title text not null,
    type text not null, -- 'genel', 'isg', 'finans'
    content text, -- Oluşturulan rapor metni
    input_text text, -- Kullanıcının girdiği ham veri (opsiyonel)
    status text default 'completed', -- 'draft', 'processing', 'completed'
    created_at timestamp with time zone default timezone('utc'::text, now()) not null
  );

  -- RLS (Güvenlik) Aç
  alter table public.reports enable row level security;

  -- Kullanıcı SADECE kendi raporlarını görebilir, ekleyebilir, silebilir
  create policy "Users can view own reports" on public.reports for select using ( auth.uid() = user_id );
  create policy "Users can insert own reports" on public.reports for insert with check ( auth.uid() = user_id );
  create policy "Users can update own reports" on public.reports for update using ( auth.uid() = user_id );
  create policy "Users can delete own reports" on public.reports for delete using ( auth.uid() = user_id );

  -- 3. Yeni üye olunca otomatik profil oluşturma (Trigger)
  create or replace function public.handle_new_user()
  returns trigger as $$
  begin
    insert into public.profiles (id, email, full_name)
    values (new.id, new.email, new.raw_user_meta_data->>'full_name');
    return new;
  end;
  $$ language plpgsql security definer;

  create trigger on_auth_user_created
    after insert on auth.users
    for each row execute procedure public.handle_new_user();
